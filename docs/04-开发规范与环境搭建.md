## 1. 开发环境

### 1.1 硬性要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / 11 x64 | PyInstaller 不能交叉编译，必须在 Windows 本机打包 |
| Python | **3.12（64 位）** | 统一由 miniconda 的 `game` 环境提供 |
| conda | miniconda（支持 `conda create`） | 负责解释器隔离，不使用 venv |
| pip | ≥ 23.0 | 保证安装 wheel，不触发源码编译 |
| 编辑器 | IntelliJ IDEA（Python 插件） | 解释器指向 conda `game`，支持 pytest 与类型提示 |
| 音频设备 | 任意（可无） | 无声卡时游戏静默运行，但开发阶段建议有声卡以便验证音效 |

> 环境统一由 conda 管理。安装依赖前先用 `where python` 确认第一条路径在 miniconda 的 `envs\game` 下，否则依赖会装进 base 或系统 Python。

### 1.2 创建 conda 环境

```powershell
conda create -n game python=3.12 -y
conda activate game
python --version          # 应输出 Python 3.12.x
```

若提示 `conda` 不是可执行命令，先打开「Anaconda Prompt (miniconda3)」；之后可 `conda init powershell` 让 PowerShell 直接可用。

### 1.3 IDEA 工程配置

1. `File → Project Structure → SDKs → Add SDK → Conda Environment`，选择 `game`。
2. `Run → Edit Configurations → + → Python`：Script path 指向 `main.py`，Working directory 设为工程根（`游戏/俄罗斯方块`）。
3. 右下角解释器路径应包含 `envs\game`，切换后 `import pygame` 不报错。

### 1.4 依赖安装

`requirements.txt`：

```text
pygame>=2.5.2,<2.7
pyinstaller>=6.3,<7
pytest>=7.4
pillow>=10.0        # 仅 tools/ 生成素材时需要，运行与打包不需要
numpy>=1.26         # 仅 tools/ 生成音频时需要，运行与打包不需要
```

```powershell
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python -m pip freeze > requirements-lock.txt
```

> `pillow` 与 `numpy` 只用于重新生成素材，不要写进 spec 的 hiddenimports；打包时 PyInstaller 依据 import 链自动排除它们。若担心被误收集，在 spec 的 `excludes` 中显式排除。

### 1.5 首次冒烟验证

```powershell
python -c "import sys; print(sys.version); print(sys.executable)"
python -c "import pygame; print(pygame.version.ver)"
python -c "import pygame; pygame.mixer.init(); print('mixer ok')"
python main.py
```

应弹出 720×800 窗口并进入主菜单，能听到 BGM；点「开始游戏」后方块开始下落。

## 2. 工程与命名规范

### 2.1 目录约定

- 源码一律放 `src/`，入口仅 `main.py` 一个；`src/ui/` 为表现层子包。
- 二进制资源放 `assets/`，**只能**通过 `resource_path()` 访问。
- 素材生成脚本放 `tools/`，不参与打包，也不进入 `assets/`。
- 测试放 `tests/`，文件名 `test_*.py`，不得 import pygame。
- 临时脚本、实验代码放 `scratch/`（加入 `.gitignore`）。
- 截图放 `screenshots/`，由发版前人工补齐，不作为运行时资源。

### 2.2 命名规则

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块 | 小写下划线 | `pieces.py`、`effects.py` |
| 类 | 大驼峰 | `Board`、`SevenBag`、`Renderer` |
| 函数/方法 | 小写下划线，动词开头 | `try_rotate`、`clear_rows`、`take_events` |
| 私有成员 | 单下划线前缀 | `_touch_lock`、`_bag` |
| 常量 | 全大写 | `LOCK_DELAY_MS`、`CELL` |
| 枚举成员 | 全大写 | `GameState.PLAYING` |
| 布尔量 | `is_` / `has_` / `can_` 前缀 | `lock_active`、`hold_used` |

### 2.3 代码风格

- PEP 8，单行 ≤ 100 字符，缩进 4 空格，UTF-8 无 BOM。
- 公开函数写类型注解；结构化数据用 `dataclass`，不用裸 dict。
- 关键算法（SRS 偏移、碰撞、消行、7-bag、DAS）必须写中文注释说明**为什么**，而不是复述代码。
- 单个函数尽量 ≤ 100 行；`main()` 主循环按分支分段并加注释，允许更长。
- 禁止裸 `except:`；捕获需指明类型，并在注释中说明降级行为。
- 禁止在业务模块中 `print` 调试；未捕获异常写 `%APPDATA%\TetrisDesktop\crash.log`。
- 格式化与静态检查建议：

```powershell
pip install black ruff
black --line-length 100 .
ruff check .
```

### 2.4 依赖方向的硬约束

以下为 Code Review 阻断项：

1. `pieces.py`、`board.py`、`game.py` 不得 import `pygame`。
2. `ui/` 只能读快照，不得修改 `Board` / `Game` 的字段。
3. `game.py` 不得 import `audio` / `storage` / `ui`；音效由 `main.py` 消费事件后播放。
4. 任何位置不得出现 `"assets/"` 形式的字面路径。
5. 任何位置不得写入 exe 所在目录（统一写 `%APPDATA%`）。

自查：

```powershell
Select-String -Path src\*.py,src\ui\*.py -Pattern "import pygame|assets/|assets\\"
```

## 3. 版本控制规范

`.gitignore`：

```gitignore
__pycache__/
*.pyc
build/
dist/
*.spec.bak
scratch/
.pytest_cache/
requirements-lock.txt
_src/
.idea/workspace.xml
```

> `tetris.spec` 与 `version_info.txt` 需要入库（它们定义打包结果）；`build/`、`dist/` 不入库；`_src/` 是 AI 生成的原图，体积大且可由 `tools/` 重新处理，不入库但建议本地留档。

提交信息（Conventional Commits 精简版）：

```
feat(pieces): 实现 SRS 旋转与踢墙
fix(game): 锁定延迟重置次数超限后立即锁定
docs(pack): 补充音频文件未打包的排查
test(board): 覆盖一次消四行的行号平移
chore(assets): 重新生成方块贴图
```

一次提交只做一件事，重构与功能分开。

## 4. 调试与开发辅助

### 4.1 调试开关

`config.py` 中：

```python
DEBUG = False        # 发布前必须为 False
```

`DEBUG=True` 时允许：窗口标题显示 FPS 与当前状态、打印存档路径、绘制碰撞边框、输出事件流。发布版必须关闭，并删除所有控制台输出。

### 4.2 固定局面复现

`tests/` 与调试时常需构造地形。`Board` 提供测试注入：

```python
def load_from(self, rows: list[str]):
    """按字符画构造地形：'.' 空，'I''J''L''O''S''T''Z' 为对应颜色。"""
    for r, line in enumerate(rows):
        for c, ch in enumerate(line):
            self.grid[r][c] = 0 if ch == "." else ch
```

用法（构造「只差一列就满」的局面）：

```python
board.load_from([
    "IIIIIIIIII",
    "IIIIIIIIII",
    "IIIIIIIII.",
    "IIIIIIIIII",
])
```

### 4.3 无头测试

`pytest` 不需要显示设备，因为模型层不 import pygame。若测试意外引入 pygame：

```powershell
$env:SDL_VIDEODRIVER="dummy"
$env:SDL_AUDIODRIVER="dummy"   # 如需初始化 mixer
```

### 4.4 素材修改流程

1. 改 `tools/gen_sprites.py` 或 `tools/gen_audio.py` 中的参数／配色／旋律。
2. 重新执行：

```powershell
python tools\gen_sprites.py
python tools\gen_audio.py
```

3. 目视／试听确认，再提交新的二进制素材；**不要**手工编辑 `assets/` 下的文件后再让脚本与产物不一致。

## 5. 开发节奏建议

按「模型先行、表现后行、音频最后接入」推进，每步都可独立验证：

| 阶段 | 产出 | 验收 |
| --- | --- | --- |
| 1 | `config.py` + `pieces.py` + `tests/test_pieces.py` | 旋转与踢墙用例全绿 |
| 2 | `board.py` + `tests/test_board.py` | 碰撞、消行、行号平移正确 |
| 3 | `game.py` + `tests/test_game.py` | 重力、锁定、计分、7-bag、暂存正确 |
| 4 | `storage.py` + `resource.py` | 坏 JSON 不崩，路径兼容两种运行方式 |
| 5 | `ui/theme.py` + `renderer.py`（静态绘制） | 棋盘、面板、字体、贴图正确 |
| 6 | `ui/effects.py` + `ui/display.py` | 消行闪烁、抖动、全屏缩放与点击映射 |
| 7 | `audio.py` + 事件接入 | 9 个音效与 BGM 音量、暂停行为正确 |
| 8 | 菜单 / 设置 / 排行榜 / 昵称 | 界面流转与持久化完整 |
| 9 | 打包 | 06 文档验收清单全通过 |

每个阶段结束都应能运行、能提交、能截图。

## 6. 常见环境问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `pip install pygame` 报 `Microsoft Visual C++ 14.0 required` | Python 版本/架构无对应 wheel | 确认 `python -V` 为 3.12 x64，在 `game` 环境内安装 |
| `pygame.error: No available video device` | 无图形会话（远程/服务） | 本地桌面运行；或 `SDL_VIDEODRIVER=dummy` 仅测试 |
| `pygame.error: WASAPI can't initialize audio client` | 无声卡、音频服务被禁用 | 正常现象，`Audio` 已降级；开发时可在设置里把音效关掉 |
| 中文显示成方块 | 未加载中文字体 | 使用 `assets/fonts/msyh.ttc`，经 `resource_path` 加载 |
| 窗口一闪而过 | 主循环异常且无控制台 | 终端里 `python main.py` 看堆栈 |
| 高 DPI 下文字发虚 | 未声明 DPI 感知 | `pygame.init()` 前调用 `SetProcessDpiAwareness(1)`（06 §6.5） |
| 方块贴图错位 | `blocks.png` 被重新导出为非 8×64 比例 | 重新跑 `tools/gen_sprites.py`，不要手工裁图 |
| 音效延迟明显 | mixer buffer 过大 | `mixer.init(buffer=512)`；不要用默认 4096 |
| IDEA 报 `ModuleNotFoundError: pygame` | 解释器指向 base/系统 Python | 切换 SDK 到 conda `game` |
| PyInstaller 报找不到 pygame | 打包环境与运行环境不一致 | 在同一个 `game` 环境内安装并打包 |
