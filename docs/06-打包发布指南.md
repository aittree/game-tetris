## 1. 打包原理（先理解再操作）

PyInstaller 不是把 Python 编译成机器码，而是把解释器、依赖包与资源打成一个包：

1. `Analysis` 阶段：从 `main.py` 出发静态分析 import 链，收集 `.py`、扩展模块（`.pyd`）、DLL。
2. `PYZ`：纯 Python 模块编译成字节码并归档。
3. `EXE`：把 bootloader + 归档 + 资源拼成 exe。
4. **运行时（onefile）**：exe 启动后把自己解包到 `%TEMP%\_MEIxxxxxx`，再以该目录为工作目录启动解释器。
5. 因此脚本内有两个关键事实：
   - `sys.frozen == True`（处于打包环境）
   - `sys._MEIPASS` 指向解包目录，**所有资源必须从这里找**

这解释了三个常见现象：exe 启动比脚本慢 1～2 秒、资源路径必须特殊处理、onefile 的自解压行为容易被杀软标记。

> 本项目比 2048 多一类资源：**音频**。音频是普通数据文件，必须和其它素材一起写进 `datas`，否则运行时 `pygame.mixer.Sound` 会抛 `FileNotFoundError`（代码已捕获，但表现为「没有声音」）。

## 2. 打包前置检查

在**同一个 conda `game` 环境**内完成（打包环境必须与运行验证环境一致）：

```powershell
# 1. 确认环境（版本应为 3.12.x，executable 路径含 envs\game）
python -c "import sys; print(sys.version); print(sys.executable)"

# 2. 确认依赖
python -c "import pygame; print(pygame.version.ver)"
pyinstaller --version

# 3. 确认素材齐全
Test-Path assets\icon.ico, assets\icon.png, assets\fonts\msyh.ttc
Test-Path assets\images\bg_menu.png, assets\images\bg_game.png
Test-Path assets\images\logo.png, assets\images\blocks.png
(Get-ChildItem assets\audio\*.wav).Count      # 应为 10

# 4. 确认脚本可运行
python main.py
```

| 检查项 | 不通过的后果 |
| --- | --- |
| 不在 `game` 环境内打包 | 体积暴涨或版本错乱 |
| pygame 与打包同环境 | exe 启动报 `ModuleNotFoundError: pygame` |
| 字体/贴图/音频缺失 | 中文方块字、方块变纯色或无声 |
| `main.py` 跑不起来 | 打出来的 exe 一定是坏的 |

## 3. 打包形态选择

| 形态 | 命令 | 产物 | 体积 | 启动 | 适用 |
| --- | --- | --- | --- | --- | --- |
| **onefile** | `-F` | 单个 `俄罗斯方块.exe` | 约 42～50 MB（字体 18.8 MB 占大头） | 冷启 1.5～3 s | 首选，分发最简 |
| **onedir** | `-D` | 一个文件夹（exe + `_internal` + assets） | 总量相近 | 快（无需解包） | 被杀软误报、启动慢、内网部署 |

建议：**先出 onefile 作为交付物，同时保留 onedir 作为排障版本**。两种形态代码完全不用改——前提是资源路径严格走 `resource_path()`（onedir 下 `sys._MEIPASS` 指向 `_internal`，函数自动兼容）。

## 4. 命令行快速打包（首次验证）

```powershell
pyinstaller -F -w -i assets\icon.ico --add-data "assets;assets" --name 俄罗斯方块 main.py
```

| 参数 | 作用 |
| --- | --- |
| `-F` / `--onefile` | 打成单文件 |
| `-w` / `--noconsole` | 不显示命令行黑窗（GUI 必须加） |
| `-i` / `--icon` | exe 图标，必须 `.ico` |
| `--add-data "源;目标"` | 资源入包，Windows 用**分号**分隔 |

产物：`dist\俄罗斯方块.exe`。先双击验证，再改成 spec 正式构建。

> 文件名保持 `俄罗斯方块.exe`（不含括号，便于命令行与脚本引用）；窗口标题与 exe 属性页中的产品显示名统一为「俄罗斯方块（Tetris）」。

> 排障：exe 一闪而过看不到错误时，去掉 `-w` 重打一版（`--name tetris_debug`），运行后堆栈会打印到控制台。

## 5. 正式构建：spec 文件

命令行参数多且易漏，正式构建统一用 `tetris.spec`（入库，作为唯一构建入口）。

### 5.1 onefile 版 spec

```python
# -*- mode: python ; coding: utf-8 -*-
# tetris.spec —— onefile 单文件构建配置
# 用法：pyinstaller tetris.spec --clean --noconfirm

block_cipher = None

datas = [
    ("assets", "assets"),          # 图标、字体、图片、音频整体入包
]

a = Analysis(
    ["main.py"],
    pathex=[],
    binaries=[],
    datas=datas,
    hiddenimports=["pygame.sysfont"],
    hookspath=[],
    hooksconfig={},
    runtime_hooks=[],
    excludes=["tkinter", "pytest", "tools", "numpy", "PIL"],
    noarchive=False,
)

pyz = PYZ(a.pure)

exe = EXE(
    pyz,
    a.scripts,
    a.binaries,
    a.datas,
    [],
    name="俄罗斯方块",
    debug=False,
    bootloader_ignore_signals=False,
    strip=False,
    upx=False,                      # 关掉 UPX，降低杀软误报
    upx_exclude=[],
    runtime_tmpdir=None,
    console=False,                  # True 会带黑窗
    disable_windowed_traceback=False,
    argv_emulation=False,
    target_arch=None,
    codesign_identity=None,
    entitlements_file=None,
    icon=["assets/icon.ico"],
    version="version_info.txt",
)
```

说明：

- `hiddenimports=["pygame.sysfont"]`：`SysFont` 兜底时会走该模块，部分 PyInstaller 版本不会自动收集。
- `excludes` 中排除 `tools`、`numpy`、`PIL`：素材生成脚本与依赖只在开发期使用，误打包会让体积增加 20 MB 以上。
- `Analysis` 的 `optimize` 参数自 PyInstaller 6.10 才支持；本项目按 6.3+ 编写，不传该参数。

### 5.2 onedir 版 spec

与上面相同，只把 `EXE(...)` 的 `a.binaries, a.datas` 移除，并追加 `COLLECT`：

```python
exe = EXE(
    pyz, a.scripts, [],
    exclude_binaries=True,
    name="俄罗斯方块",
    debug=False,
    strip=False,
    upx=False,
    console=False,
    icon=["assets/icon.ico"],
    version="version_info.txt",
)

coll = COLLECT(
    exe, a.binaries, a.datas,
    strip=False,
    upx=False,
    name="俄罗斯方块",
)
```

产物：`dist\俄罗斯方块\`（含 `俄罗斯方块.exe`、`_internal\`、`assets\`）。

## 6. 打包相关的代码要点

### 6.1 资源路径（唯一正确写法）

```python
def resource_path(*parts):
    if getattr(sys, "frozen", False):
        base = getattr(sys, "_MEIPASS")          # 私有属性，用 getattr 避免静态检查告警
    else:
        base = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
    return os.path.join(base, *parts)
```

禁止写法：`open("assets/audio/bgm_main.wav")`、`os.path.join(os.getcwd(), ...)`。onefile 下当前工作目录是**用户启动 exe 的目录**，既不是 exe 所在目录，也不是解包目录。

### 6.2 字体：必须随包

- 打包 `assets/fonts/msyh.ttc`，用 `pygame.font.Font(resource_path(...), size)` 加载。
- 不要只依赖 `SysFont("microsoftyahei")`：精简版系统可能没有该字体，结果是方块字。
- `msyh.ttc` 实测 18.8 MB，是体积最大项。若必须压到 30 MB 内，用 `fonttools` 做子集化（只保留 0-9、A-Z 与界面用到的汉字）；子集化后每新增一个汉字都要同步更新字符集，否则显示缺字。

### 6.3 图标：exe 用 `.ico`，窗口用 `.png`

- `assets/icon.ico`：给 PyInstaller，需含 16/32/48/64/128/256 多尺寸（本项目由 `tools/gen_sprites.py` 一次生成）。
- `assets/icon.png`（256×256）：给 `pygame.display.set_icon()`。
- 原因：`pygame.image.load` 对多尺寸 `.ico` 的支持依赖 SDL_image 的 ICO 解码器，偶发报错或取错尺寸；png 最稳，代码里对图标加载做 try/except 降级。

### 6.4 音频：三件事必须做对

1. **文件要在 `datas` 里**：`("assets", "assets")` 已包含 `audio/`；不要只放 `images` 与 `fonts`。
2. **加载要 try/except**：`pygame.mixer.Sound` 在文件缺失或格式异常时抛 `pygame.error`，启动阶段不能让整个游戏崩掉。
3. **初始化要早**：`pygame.mixer.init(...)` 放在 `pygame.init()` 之后、主循环之前；若初始化失败，`Audio.available=False`，后续播放全部空操作。

```python
try:
    pygame.mixer.init(frequency=22050, size=-16, channels=1, buffer=512)
except pygame.error:
    available = False          # 无声卡环境：静默降级
```

WAV 为未压缩 PCM，10 个文件共约 1.5 MB，不需要额外解码库；不要换成 MP3（会引入 ffmpeg/av 依赖，体积与兼容性都变差）。

### 6.5 高 DPI

打包后窗口在高缩放屏幕上可能发虚。在 `pygame.init()` 之前声明 DPI 感知：

```python
import ctypes

def enable_dpi_awareness():
    try:
        ctypes.windll.shcore.SetProcessDpiAwareness(1)   # Win8.1+
    except (AttributeError, OSError):
        try:
            ctypes.windll.user32.SetProcessDPIAware()    # Win7 兜底
        except (AttributeError, OSError):
            pass
```

调用失败不影响运行。

### 6.6 标准输出与编码

`-w` 打包后 `sys.stdout` 可能为 `None`，任何 `print()` 都可能抛 `AttributeError`。发布版必须：

- 移除所有调试 `print`；
- 日志写文件而非控制台；
- 全局异常兜底：

```python
def main():
    try:
        _run()
    except Exception:
        import traceback
        from pathlib import Path
        log = Path(os.environ.get("APPDATA", ".")) / "TetrisDesktop" / "crash.log"
        log.parent.mkdir(parents=True, exist_ok=True)
        log.write_text(traceback.format_exc(), encoding="utf-8")
        raise
```

### 6.7 存档目录

统一写 `%APPDATA%\TetrisDesktop\save.json`。exe 可能放在 `C:\Program Files` 或只读共享盘，写同级目录会失败。

## 7. 构建与验证流程

### 7.1 标准构建命令

```powershell
# 0. 激活环境（Python 3.12）
conda activate game

# 1. 清理旧产物（避免旧 build 缓存混入）
Remove-Item -Recurse -Force build, dist -ErrorAction SilentlyContinue

# 2. 构建
pyinstaller tetris.spec --clean --noconfirm

# 3. 查看结果
Get-ChildItem dist
Get-Item "dist\俄罗斯方块.exe" | Select-Object Name, Length, LastWriteTime
```

构建日志重点看三处：

- `WARNING: Hidden import ... not found`（多数无害，涉及 pygame/SDL 的要查）。
- `ERROR:` 行——有 ERROR 基本构建失败。
- 最后出现 `Building EXE from EXE-00.toc completed successfully.` 才算成功。

### 7.2 本地验证（5 分钟）

```powershell
# 1. 直接运行
.\dist\俄罗斯方块.exe

# 2. 版本信息与图标
(Get-Item ".\dist\俄罗斯方块.exe").VersionInfo | Format-List FileDescription, ProductName, FileVersion

# 3. 存档生成
Test-Path "$env:APPDATA\TetrisDesktop\save.json"

# 4. 哈希留档
Get-FileHash ".\dist\俄罗斯方块.exe" -Algorithm SHA256
```

手工验证项见 05 文档第 5 节（PKG-01～10），**必须包含音频与素材完整性检查**。

### 7.3 干净机器验证

不能只在开发机验证。任选其一：

- 另一台未装 Python 的 Windows 电脑；
- 本机新建普通用户账户（不装 Python）；
- Windows 沙盒（需开启功能，无持久化）。

重点：能启动、中文字体正常、有声音、能存档、关闭无残留。

### 7.4 一键构建脚本（`build.ps1`）

```powershell
$ErrorActionPreference = "Stop"
Set-Location $PSScriptRoot

$ver = conda run -n game python -c "import sys; print(sys.version.split()[0])"
if ($ver -notlike "3.12*") { throw "请在 conda game 环境（Python 3.12）中构建，当前: $ver" }

conda run -n game python -m pytest -q
if ($LASTEXITCODE -ne 0) { throw "单元测试未通过，终止打包" }

conda run -n game pyinstaller tetris.spec --clean --noconfirm
if ($LASTEXITCODE -ne 0) { throw "打包失败" }

$exe = Get-Item ".\dist\俄罗斯方块.exe"
"构建成功: $($exe.FullName)  $([math]::Round($exe.Length / 1MB, 1)) MB"
```

> 已手动 `conda activate game` 时，可去掉 `conda run -n game` 前缀，两种方式等价。

## 8. 体积优化（可选）

首次 onefile 通常 42～50 MB。要压缩时按顺序做：

1. **先量后减**：用 `-D` 构建 onedir，查看 `dist\俄罗斯方块\_internal\` 里谁最大（通常是 `msyh.ttc` 与 SDL2 DLL）。
2. 确认 `excludes` 已排除 `numpy`、`PIL`、`tools`、`pytest`。
3. **字体子集化**是唯一的大杠杆：可省 8～12 MB，但必须维护字符集，界面新增文案时容易缺字。
4. 不要盲目排除 `logging`、`email`、`http`、`xml`、`asyncio` 等标准库，pygame 与 PyInstaller 钩子可能间接依赖，表现为启动即 `ModuleNotFoundError`。
5. 音频已是 WAV 且仅 1.5 MB，没必要转码。
6. UPX 能再省 30%～50%，但**不建议对外分发**：UPX 壳是杀软误报重灾区。

结论：本项目体积主要矛盾是字体，不是功能；**优先保证能跑、不误报**，45 MB 左右可接受。

## 9. 常见问题与排查（按现象查）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| exe 双击闪退、无提示 | 异常在初始化阶段抛，`-w` 吞了堆栈 | 用 `--console` 重打看 traceback；加 6.6 的 crash.log |
| `ModuleNotFoundError: No module named 'pygame'` | 打包环境未装 pygame 或环境不对 | 在 `game` 环境安装后重打；spec 加 `hiddenimports=["pygame"]` |
| 启动即报 `pygame.error` 但游戏能玩 | 音频初始化异常被捕获 | 属正常降级；检查声卡/驱动，`Audio.available` 应为 False |
| **有画面但完全没有声音** | `assets/audio` 没进包，或 `music` 音量为 0 | 检查 spec `datas`；解包目录下应有 `assets/audio/*.wav`；查看存档音量 |
| 音效有、BGM 没有 | `bgm_main.wav` 加载失败或 `music_volume=0` | 重新生成音频；确认 `pygame.mixer.music.play(-1)` 被调用 |
| 启动报找不到 `msyh.ttc` | 字体未打包或路径没走 `resource_path` | 检查 `datas` 与 `sys._MEIPASS`；用 `--add-data "assets;assets"` |
| 中文全是方块/问号 | 字体未随包且系统无中文字体 | 打包 `msyh.ttc`；`font.render(..., True, color)` 开抗锯齿 |
| 方块全是纯色、没有质感 | `blocks.png` 未打包或尺寸被改 | 重新生成贴图；确认 `assets/images/blocks.png` 为 512×64 |
| 窗口无图标 / 属性页无图标 | 未传 `-i` 或 ico 缺尺寸 | 用 `tools/gen_sprites.py` 生成多尺寸 ico |
| `File is not a Windows BMP file` | 把 ico 传给 `display.set_icon` | 窗口图标用 png，ico 只给 PyInstaller |
| 启动 3～5 秒才出窗口 | onefile 每次解包 | 改 onedir；或用 splash 启动图 |
| 杀软报 `Trojan:Win32/Wacatac` | 无签名 + 自解压 + 无版本信息 | 换 onedir、加 version_info、避免 UPX、提交误报、买代码签名 |
| 高分屏字体发虚 | 未声明 DPI 感知 | 见 6.5 |
| 存档写不进去 | exe 在只读目录 / 权限不足 | 确认写 `%APPDATA%`；`save_profile` 已 try/except 降级 |
| 体积 > 70 MB | 误把 `numpy`/`PIL`/`tools` 打包，或 `_src` 大图被收进 assets | 检查 spec `excludes`；把 `_src/` 移出 assets |
| 提示缺 `vcruntime140.dll` | 目标机缺 VC++ 运行库 | 安装「Microsoft Visual C++ 2015-2022 Redistributable (x64)」 |
| 打包报 `PermissionError: dist\...exe` | 上一版 exe 仍在运行 | 任务管理器结束后重试 |
| 每次产物内容都变 | `build/` 缓存残留 | 构建前清理 `build`、`dist` |

## 11. 版本与分发建议

- 版本格式 `主版本.次版本.修订号`：规则/功能变更升次版本，修 Bug 升修订号。
- 分发渠道：内网共享盘、网盘、飞书/企业微信群文件；提示「若被浏览器或杀软拦截，请选择保留」。
- 长期对外分发建议购买代码签名证书（OV/EV），可显著降低 SmartScreen 与杀软拦截率。
- 每次发布保留一个 onedir 版本在内部归档，用于复现用户问题。
