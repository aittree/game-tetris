## 1. 设计目标

1. **规则可测**：旋转、碰撞、消行、计分、7-bag 全部做成纯逻辑，不 import pygame，`pytest` 可覆盖。
2. **表现可换**：渲染层只消费只读快照；换皮肤、换分辨率、甚至换框架（pyglet/Qt）时模型不动。
3. **音频可降级**：任何一台没有声卡、或 mixer 初始化失败的机器，游戏仍能完整运行。
4. **打包无损**：同一份代码既能 `python main.py` 跑，也能打成单文件 exe；资源路径逻辑只有一处。
5. **规模克制**：单人开发，约 2200 行（含测试与注释）；不引入 ECS、事件总线等重架构。

## 2. 总体架构

采用**简化四层架构**：模型层、应用层、表现层、基础设施；依赖方向严格单向向下，基础设施可被任意层引用，但不得反向依赖业务层。

```
┌─────────────────────────────────────────────────────────────┐
│ 表现层 Presentation                src/ui/                   │
│  theme.py（配色/字号/布局） renderer.py（棋盘与界面绘制）      │
│  effects.py（消行闪烁/抖动/落点高亮） display.py（窗口/全屏）  │
│        ▲ 只读快照，只绘制，不改模型                            │
└────────┼────────────────────────────────────────────────────┘
         │
┌────────┼────────────────────────────────────────────────────┐
│ 应用层 Application            main.py / game.py              │
│  ┌──────────────────────┐   ┌───────────────────────────┐   │
│  │ main.py              │   │ game.py                   │   │
│  │ 界面状态机 + 主循环   │◄─►│ 一局游戏：重力/锁定/计分   │   │
│  │ 输入映射 + 存档协调   │   │ 暂存/预览/结束判定         │   │
│  └──────────────────────┘   └───────────────────────────┘   │
└────────┬──────────────────────────┬─────────────────────────┘
         │                          │
┌────────┼──────────────────────────┼─────────────────────────┐
│ 模型层 Model                      │   基础设施 Infra          │
│  pieces.py（形状/旋转/踢墙/bag）   │  storage.py（存档/榜单）  │
│  board.py（地形/碰撞/消行）        │  resource.py（资源路径）  │
│  config.py（常量/配色/速度表）      │  audio.py（BGM/SFX）     │
└───────────────────────────────────┴──────────────────────────┘
```

**分层依赖规则**（Code Review 阻断项）：

| 模块 | 允许依赖 | 禁止依赖 |
| --- | --- | --- |
| `config.py` | 标准库 | 其他业务模块 |
| `pieces.py` | 标准库（random）、config | pygame、board、game |
| `board.py` | config | pygame、pieces 之外的表现层 |
| `game.py` | pieces、board、config | pygame、ui、audio、storage |
| `storage.py` / `resource.py` | 标准库 | pygame、ui、game |
| `audio.py` | pygame.mixer、resource | board、game |
| `ui/*` | pygame、config、只读快照 | 修改 board / game 内部状态 |
| `main.py` | 全部 | — |

## 3. 模块划分

| 模块 | 职责 | 对外主要接口 |
| --- | --- | --- |
| `main.py` | 初始化 pygame/音频，驱动「菜单 / 游戏 / 设置 / 排行榜 / 昵称」界面状态机与主循环 | `main()` |
| `config.py` | 画布与棋盘尺寸、配色、速度表、计分表、DAS/ARR、音量与昵称上限、应用名与版本 | 常量 |
| `pieces.py` | 七种方块的 4×4/3×3/2×2 矩阵、SRS 旋转与踢墙表、7-bag 生成器 | `Piece`、`rotate_cw()`、`try_rotate()`、`SevenBag.next()` |
| `board.py` | 22×10 地形；碰撞检测；锁定；整行消除；快照导出 | `Board.collides(cells)`、`Board.lock(piece)`、`Board.clear_lines()`、`Board.cell_rows()` |
| `game.py` | 一局的状态：当前方块、队列、暂存、分数、等级、行数、重力与锁定计时、结束判定 | `Game.handle(action)`、`Game.update(dt_ms)`、`Game.snapshot()` |
| `storage.py` | 读写 `save.json`：最高分、设置、排行榜；容错与原子写 | `load_profile()`、`save_profile()`、`insert_record()` |
| `resource.py` | 统一资源定位：源码运行走工程根，exe 运行走 `sys._MEIPASS` | `resource_path(*parts)` |
| `audio.py` | BGM 循环、音效播放、音量控制、设备缺失降级 | `Audio.play(name)`、`set_music_volume()`、`set_sfx_volume()`、`pause()` |
| `ui/theme.py` | 方块色、字号、卡片与面板矩形、按钮布局 | `piece_color()`、`cell_rect()`、`board_rect()` 及布局常量 |
| `ui/renderer.py` | 每帧绘制棋盘、面板、菜单、设置、排行榜、昵称、浮层；按钮命中检测 | `Renderer.draw_game()`、`draw_menu()`、`hit_*()` |
| `ui/effects.py` | 消行闪烁、Tetris 抖动、落点高亮、分数跳动 | `Effects.on_clear(rows)`、`update(dt)`、`offset()` |
| `ui/display.py` | 720×800 画布与窗口/全屏呈现，鼠标坐标映射 | `Display(canvas, fullscreen)`、`to_canvas(pos)`、`present()` |

## 5. 运行时模型

- **单线程 + 单主循环**：`while running: 处理事件 → 推进 game(dt) → 更新特效 → 绘制 → present → clock.tick(60)`。音频在独立 mixer 通道，不占主线程。
- **时间基准**：一切计时（重力、锁定延迟、DAS/ARR、消行动画）都用 `dt_ms` 累加，不用 `pygame.time.get_ticks()` 做逻辑判断，保证暂停/掉帧行为一致。
- **输入模型**：`KEYDOWN`/`KEYUP` 被翻译成抽象动作（`MOVE_LEFT`、`MOVE_RIGHT`、`ROTATE_CW`、`ROTATE_CCW`、`SOFT_DROP`、`HARD_DROP`、`HOLD`、`PAUSE`、`RESTART`），`game.py` 不认识 pygame 键值。
- **连发模型**：左右移动与软降由 `main.py` 维护按键状态与 DAS/ARR 计时器，在每帧向 `Game` 发动作；不使用 `pygame.key.set_repeat`（其延迟固定为系统值，无法控制 ARR）。
- **状态机**：

```
        ┌──────────┐  开始     ┌───────────┐  P/ESC  ┌──────────┐
        │   MENU   ├──────────►│  PLAYING  ├────────►│  PAUSED  │
        └────┬─────┘           └─────┬─────┘◄────────┤          │
             │                      │ 顶出/锁出       └────┬─────┘
             │ 退出                  ▼                     │ 重开
             │                 ┌────────────┐             │
             └────────────────►│ GAME_OVER  │◄────────────┘
                               └────────────┘
```

- `MENU / SETTINGS / RANKING / ENTRY` 属于界面状态，只存在于 `main.py`；`PLAYING / PAUSED / GAME_OVER` 属于对局状态，由 `Game` 持有。暂停界面的「返回主菜单」是唯一允许对局中途回菜单的路径。
- 暂停与结束浮层是**模态**的：其下的游戏输入全部忽略，只响应浮层按钮。

## 6. 关键数据流

### 6.1 一个方块的生命周期

```
bag.next() → Piece(type, rot=0, x=3, y=0)
  → 生成重叠检测：board.collides(piece.cells()) → 是则 GAME_OVER
  → 每帧 update(dt):
       gravity_acc += dt
       if gravity_acc >= gravity_ms(level): 尝试下移一格
            ├─ 成功 → y+1, 软降分不加, lock_reset 计数随下落清零
            └─ 失败 → 进入锁定倒计时（500 ms）
       锁定倒计时到期 / 重置次数用尽 → lock()
  → lock():
       board.lock(piece) → 写入地形
       full_rows = board.full_rows()
       if full_rows: score += 表[行数] × level; lines += n
       if lines/10 > level-1: level += 1（音效）
       effects.on_clear(full_rows)
       hold_used = False
       spawn_next()
```

### 6.2 一次按键的链路

```
KEYDOWN(LEFT) → main.py 映射为 Action.MOVE_LEFT
  → Game.handle(action)
      ├─ 状态检查（PAUSED/GAME_OVER 忽略）
      ├─ piece.x -= 1；board.collides？→ 回滚（播放拒绝音？不播放）
      ├─ 成功 → 重置锁定计时（受 15 次上限约束）
  → 下一帧 Renderer.draw_game(snapshot, effects)
```

旋转同理，只是失败时会依次尝试 5 个 SRS 偏移；踢墙成功同样计入锁定重置次数。

### 6.3 存档流

```
启动 → storage.load_profile()
  ├─ 文件缺失 / 解析失败 / 字段类型错 → 默认 Profile（best=0、音量 70/80、窗口、幽灵开、空榜）
  └─ 兼容旧版只有 {"best": n} 的文件
变更（设置项 / 登记成绩 / 退出确认）→ storage.save_profile()
  ├─ 目录不存在 → 创建 %APPDATA%\TetrisDesktop
  ├─ 写 save.tmp → os.replace 原子替换
  └─ 排行榜按分数降序保留前 10
```

### 6.4 音频流

```
Audio.init()
  ├─ pygame.mixer.pre_init(22050, -16, 1, 512) → pygame.mixer.init()
  ├─ 失败（无声卡/驱动异常）→ self.available=False，后续 play 全部空操作
  ├─ BGM 载入 → Channel(0) 循环播放
  └─ SFX 预载 9 个 → 按需 Channel(1..4) 播放，找不到空闲通道则丢弃（不排队）
设置页拖动音量 → Audio.set_music_volume(v) / set_sfx_volume(v)
暂停 → Audio.pause()（暂停 BGM）；继续 → Audio.resume()（按原位置续播）
```

## 7. 关键设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 棋盘表示 | `list[list[int]]`，0 空、1 占用（颜色由方块类型决定另存颜色图） | 碰撞判断最快；颜色单独一张 `color_grid`，消行时同步平移 |
| 方块表示 | 每个类型 4 个旋转态矩阵 + SRS 偏移表 | 避免运行时矩阵旋转带来的中心漂移，状态与 SRS 完全一致 |
| 旋转实现 | 先旋转矩阵，再按 (dx, dy) 偏移尝试 5 次 | 与官方 SRS 行为一致；偏移表可被单元测试直接断言 |
| 重力 | 毫秒累计而非帧计数 | 掉帧、暂停、切全屏都不会让速度漂移 |
| 锁定延迟 | 500 ms + 15 次重置上限 | 手感接近现代 guideline，同时避免无限拖时间 |
| 7-bag | 独立生成器类，可注入随机种子 | 可测试「70 个方块每种恰好 10 次」 |
| 渲染 | 方块用 `blocks.png` 贴图缩放绘制，叠色由贴图本身承担 | 贴图带高光/圆角，比 `draw.rect` 更有质感；一张图 8 格便于换皮 |
| 消行动画 | 逻辑即时结算 + 视觉层闪烁 | 与 2048 同思路：规则不受动画影响 |
| 音频 | `pygame.mixer` + 预载 WAV | 无需额外解码库，onefile 打包体积可控 |
| 字体 | 随包 `msyh.ttc` | 目标机字体不确定，避免方块字 |
| 打包 | onefile 首选，onedir 备选 | 分发最简；杀软误报时切 onedir |

## 8. 异常与容错设计

| 风险 | 处理策略 |
| --- | --- |
| 音频设备缺失 / mixer 初始化失败 | `Audio.init()` 捕获 `pygame.error`，置 `available=False`；所有播放调用变为空操作 |
| 音频文件缺失 | 单个音效加载失败只跳过该音效，不阻断启动；BGM 失败则静音运行 |
| 图片/字体缺失 | 背景缺失用纯色填充；贴图缺失回退 `pygame.draw.rect`；字体回退 `SysFont` → 默认字体 |
| 存档损坏 / 无权限 | 读：降级为默认 Profile；写：捕获异常不中断游戏，仅保留内存状态 |
| 显示器小于画布 | 窗口模式按桌面可用区域缩放窗口（仍按 720×800 逻辑绘制）；全屏等比缩放居中 |
| 高 DPI 模糊 | `pygame.init()` 之前声明 DPI 感知，见 06 §6.5 |
| 打包后找不到资源 | spec 中 `datas` 收集 `assets`，路径统一走 `resource_path()` |
| 长时间运行内存增长 | 每帧只创建必要的 Surface；`renderer` 缓存字体对象与缩放后的贴图；特效列表用完即清 |
